# Kanban

A Trello-style board built on Baseplate: email and password login, boards with lists and cards, drag to move a card, and row-level security that keeps every board private to the person who made it.

It exists to prove the whole path works, so nothing here is mocked.

## Run it

From this directory:

```bash
npx @diepen/baseplate init
npx @diepen/baseplate up --replace
npm install
```

One stack runs at a time, whatever ports it was given, so `--replace` stops whichever other project is holding them and starts this one. `baseplate down` in this directory gives them back.

The tables are made against the running database, so there is no schema file here to push:

```bash
npx @diepen/baseplate schema add-table boards --column title:text --column created_at:timestamptz
npx @diepen/baseplate schema add-table lists --column board_id:uuid --column title:text --column position:numeric
npx @diepen/baseplate schema add-table cards --column list_id:uuid --column title:text --column position:numeric
npm run db:types
```

Cards can carry files, so make the bucket they go in:

```bash
npx @diepen/baseplate storage add-bucket card-files
npm run dev
```

Open http://127.0.0.1:5273, create an account, and make a board.
Create a second account and it sees none of the first one's boards, and none of their files.

## The schema

Every table arrives with `id` and `owner_id` on it, and with row access turned on in the same transaction as the `CREATE`, so it is never readable unprotected.
That is why none of the three commands above names either column, and why there is no second step to lock a table down.

Nothing in this directory declares those tables.
`baseplate tables` is the answer to what the schema is, because it reads the database.
Adding a column later is `schema add-column`, then `npm run db:types` again.

Three things `add-table` will not do, and what this app does instead:

- **No defaults.** `created_at` is `timestamptz NOT NULL` with nothing behind it, so `src/features/boards.tsx` sends the timestamp on insert.
- **No foreign keys**, so no `ON DELETE CASCADE`. `src/cascade.ts` deletes a board's cards, then its lists, then the board.
- **No `double precision`.** A card's position is `numeric`, which holds a midpoint between two neighbours just as well.

## What the app never does

It never sends `owner_id`. The database sets it from the `sub` of the caller's token, so a client cannot claim a row belongs to someone else.

It never checks who owns a file. A card's attachments are keyed by the card id, which keeps them together, but what keeps them private is the bucket: a caller sees only the objects they put there, and knowing someone else's key gets a 404.

It never filters by user. `select()` returns what that caller is allowed to see, because the filtering is a policy in Postgres rather than a `where` clause the client could forget.

There is no anon key and no public key. `JWT_SECRET` stays on the server.

## Layout

| Path | What it is |
| --- | --- |
| `src/client.ts` | The typed Baseplate client |
| `src/database.ts` | Generated by `baseplate types`; regenerate after a schema change |
| `src/features/` | Sign in, boards, one board, one list, a card's files |
| `src/cascade.ts` | Deleting a board or a list, children first |
| `src/position.ts` | Where a card sits, as a number between its neighbours |
